# First live Jev question-learning pilot — 2026-09-18

One training-feedback proposal improved held-out development probability prediction,
but did not improve action selection and slightly worsened value MAE. The predeclared
gate rejected it and retained `pong-baseline-v1`. This is an offline negative control
result for policy improvement, with an encouraging probability-prediction signal.

## Protocol and provenance

- Actual endpoint model: `jev-1.13.0` for every request, explicitly pinned.
- Pong protocol unchanged: RAM objects/history, sticky 0.25, four-frame candidate,
  horizon 240 raw frames, then fixed `track-ball-center-v1` continuation.
- Root trajectories follow the heuristic. Warmup 120 decisions, stride 150; no roots
  selected or discarded based on future outcomes. This covers later play than the
  original mixed-policy, short-trajectory dataset; old and new results are not pooled.
- Train seeds 10/11, 16 roots each; development seeds 16/17, 12 roots each.
- Only train examples were used to write ONE proposal, frozen before development
  outcomes or predictions were inspected. The interactive coding assistant supplied
  the imported proposal, without an external teacher API or a model-weight update.
- Acceptance was declared before development evaluation: Brier reduction at least
  0.01, no value MAE increase, no sampled regret increase. No thresholds were relaxed.
- No final-test set was collected or used. No online Jev episode was run in this pilot.
- Implementation is recorded in the same Git revision as this report. Local artifacts
  live under `artifacts/pilot-v2/`; trajectories, credentials and raw logs stay out of Git.

## Train feedback and proposed change

Original training Brier was 0.837579. Many visible-ball examples received roughly
0.4 probability of gain and under 0.1 of no event, even though no-event branches were
common. Missing objects could also induce unjustified confidence in no event.

The [preserved proposal](../examples/first-event-proposals.json) distinguishes a
completed scoreless horizon from uncertainty about who wins; emphasizes that the
candidate acts for only four frames; and separates ball contact from scoring. It
also notes that later play can score even when the ball is currently missing.
Outcome definitions, observation extraction, scalar aggregation and continuation
were held fixed. This is a single assistant-authored hypothesis, not an automated
multi-round learning demonstration or a benchmark of the teacher model.

## Development results

Lower is better for all three primary metrics. Brier is the sum of three squared
probability errors (range 0–2), averaged first over actions then roots. Value MAE uses
`q = P(gain) - P(loss)` against the realized -1/0/+1 label. Sampled regret is the best
observed branch label minus the label of the chosen action, not expected-return regret.

| Predictor | Brier | Value MAE | Sampled action regret |
| --- | ---: | ---: | ---: |
| Original Jev questions | 0.864183 | 0.448889 | 0.291667 |
| Proposed Jev questions | 0.558266 | 0.454869 | 0.291667 |
| Constant train outcome frequencies | 0.561216 | 0.532697 | Not evaluated |
| Constant uniform probabilities | 0.666667 | 0.388889 | Not evaluated |

The constant-frequency control uses only train counts: loss 85/192, no event 93/192,
gain 14/192. It requires no model inference. Its Brier is only 0.002950 worse than the
candidate, so most apparent improvement could be better outcome frequency estimates
rather than useful state-dependent value discrimination. The uniform predictor's lower
MAE illustrates why a single aggregate metric is insufficient on these imbalanced labels.

Candidate Brier improved 0.305917 (35.4%), but MAE increased 0.005980; rejection reason:
`mae_regression`. On the seven informative roots, mean regret remained 1.0 for both
question programs. The fixed heuristic's regret on the same development branches was
0.208333 overall, lower than either Jev variant's 0.291667.

Brier improved on each development seed: seed 16, 0.973539 → 0.432576; seed 17,
0.754828 → 0.683956. There are only two development episodes, so this does not establish
statistical significance, generalization, or improved online game scores. The development
set has now influenced selection and must not be relabeled as final test.

## API and engineering findings

The initial real six-action request succeeded, but the first expanded-data request
exposed overly strict validation: Jev returned independently rounded two-decimal scores
and probabilities. A separate diagnostic request confirmed that behavior. Bounded
rounding tolerance and normalization were added, with original values retained and
regression tests for rejecting large discrepancies. Both compared programs used the
same revised validation. See [precision handling](protocol.md#provider-rounding).

The pilot used 82 HTTP attempts: one failed client-validation request, one diagnostic,
32 completed training predictions and 48 development predictions. All returned HTTP
200. Total provider-reported usage: 282,823 input tokens and 7,708 output tokens.
Summed HTTP wall time was 25.637 seconds, mean 0.313 seconds/request. This excludes
collection, analysis and the earlier standalone API smoke test. Billing was not queried.
The declared combined attempt cap was 100; training results were reused in `learn`.

## Reproduce

Use fresh output paths. Collect development with seeds 16/17, the same options as
train below, and 12 roots per seed. The root configuration is deterministic for the
pinned environment, but the API may not reproduce identical predictions indefinitely.

```bash
uv run jev-atari collect --seeds 10 11 --split train --behavior heuristic \
  --roots-per-seed 16 --warmup 120 --stride 150 --horizon 240 --out artifacts/repro/train
uv run jev-atari collect --seeds 16 17 --split development --behavior heuristic \
  --roots-per-seed 12 --warmup 120 --stride 150 --horizon 240 --out artifacts/repro/development
uv run --env-file "$HOME/.config/typesafe/credentials.env" jev-atari evaluate \
  --dataset artifacts/repro/train/dataset.json --backend jev --model jev-1.13.0 \
  --max-api-calls 40 --out artifacts/repro/train-eval
uv run --env-file "$HOME/.config/typesafe/credentials.env" jev-atari learn \
  --train artifacts/repro/train/dataset.json \
  --development artifacts/repro/development/dataset.json \
  --train-evaluation artifacts/repro/train-eval/evaluation.json \
  --backend jev --model jev-1.13.0 --max-api-calls 60 \
  --proposals examples/first-event-proposals.json --min-improvement 0.01 \
  --out artifacts/repro/round
```

Next experiments should measure action discrimination beyond frequency-only controls,
use more independent episodes, and keep any observation-feature redesign in a separate
comparison. TD learning and online return improvement remain unimplemented/unverified.
